## The game loop
Stand still on an unlocked **Training Pad** (`training-pads`) and the wand blows on a loop: a small bubble grows at the wand and pops every `TRAINING.blowInterval` s, paying Breath = equipped bubble's `breath` x pad `mult` x `multiplier()`. Pads unlock by rebirths: 1x/3x/4x/10x/15x/20x/50x at 0/1/2/4/5/6/8. Stand on a **Bubble Shop** pad (`bubble-shop-pads`) and hold E (`interact.js`, `INTERACT.holdMs`) to buy (Wins) or equip a bubble: that is the Breath upgrade (+1, +3, +5, +12 ... per blow). On the **Blow Zone** strip press **BLOW** (HUD button, F or E): the run in `gameplay/ride.js`. Bubble size = `BLOW.diameter(breath)`, ride distance = `RIDE.distanceMeters(breath)` (capped at the lane end), every bounce pays `bubble.breath x multiplier()` Breath, the burst pays `winsForRide(m)` = round(m / 13) x multiplier x wand mult (x2 with the Wins potion). Breath also feeds XP / Level; Level >= `LEVELS.rebirthLevel` allows Rebirth (Breath back to 1, multiplier +1, next pads).

## Decisions recorded
- Training pads blow automatically while the player stands still on an unlocked pad (Bowling Roll's auto loop), instead of a press per blow; moving pops the bubble in progress.
- The growing Blow Zone bubble sits on the avatar's -X side (in front of it in shot B, behind it in shot A, where the avatar faces the camera), then slides over the avatar at the end of the inflate.
- Ride apex is capped at `RIDE.maxApex` (4 u); the references never show it higher.
- A burst always returns the player to the Blow Zone (`BLOW_RETURN`) facing down the lane.
- Tutorial steps: train -> blow -> buy +3 (to the Blow Zone first while short of Wins) -> rebirth (train until the level allows it, then the Rebirth tile). `state.tutorial` is a saved index (the server keeps it with `$max`), so new steps only ever go on the end.

## Boxity layout
Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps its HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it. (BLOW is a HUD button; training needs no button.)
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low (static zone geometry is baked per material).
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
